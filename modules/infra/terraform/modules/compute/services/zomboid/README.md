# module "compute/services/zomboid"

A dedicated **Project Zomboid** co-op game server
(`sknnr/project-zomboid-server`) — the one service in this repo that
is *not* browser-facing HTTP, which changes how it's exposed (below).

- **`zomboid-server`** — one container, two named volumes:
  - `zomboid_data` → `/home/steam/ZomboidDedicatedServer` — the game
    install itself (downloaded/updated by SteamCMD inside the
    container on boot; first boot takes several minutes).
  - `zomboid_config` → `/home/steam/Zomboid` — saves, server options,
    logs. Wipe this and you wipe every save.

## Why there's no hostname / Access / ingress entry

Game traffic is UDP (Steam client ↔ server); Cloudflare proxies
HTTP(S) and ingress's nginx carries HTTP only, so the whole
`locals.tf` → DNS → Access → nginx pipeline doesn't apply. Instead the
container publishes its ports on **all interfaces** — directly on the
VPS's public address, the same way tela's WebRTC UDP port is
internet-reachable:

| Port  | Protocol | Use                              |
|---|---|---|
| 16261 | UDP      | Steam authentication/query        |
| 16262 | UDP      | Game/co-op traffic                |
| 27015 | TCP      | Source query — server-list pings  |

Players connect in-game via the server browser (name:
`var.server_name`) or direct `<VPS IP>:16262`.

The VPS firewall (ufw) must allow these three ports — nothing in this
repo manages it; if the server is unreachable from outside but logs
look healthy, check `sudo ufw status` before anything else.

## Credentials

Generated by root `secrets.tf`, seeded into Vaultwarden as item group
`zomboid`:

- `ZOMBOID_SERVER_PASSWORD` — join password players type in-game.
- `ZOMBOID_ADMIN_USERNAME` / `ZOMBOID_ADMIN_PASSWORD` — in-game admin
  login (for `grantadmin`, teleport, etc.).

Server name (`MeuServidorZomboid`), admin username (`admin`), and max
players (`10`) are plain variables with defaults — change and
re-apply.

## Operational notes

- First boot downloads ~2-3 GB through SteamCMD and takes a while;
  readiness shows up in `docker logs -f zomboid-server` as
  `LuaNet: Initialization [DONE]`. Don't try to join before that.
- The JVM wants a few GB of RAM headroom on a busy VPS.
- Restart policy is `unless-stopped`; saves survive restarts and
  redeploys via the two volumes above.
